- (decision) Working mode: Coaching Path. Audience: Solo maintainer/internal reference.
- (decision) Paradigm: Event-Driven / Pub-Sub. Binds: Core logic and DevOps bridges must emit autocommands rather than directly calling UI updates. Prevents: Direct imperative UI updates from background tasks that could freeze the editor.
- (decision) Plugin Orchestration: Decentralized & Strictly Lazy-Loaded via Lazy.nvim. Binds: Plugin configs must be isolated by filetype or command. Prevents: Centralized monolithic configs and global startup bloat.
- (decision) External Executions: Headless Async Jobs (vim.system) with Native UI feedback. Binds: External commands run headlessly, piping results to Quickfix/notifications. Prevents: Relying on raw terminal splits for standard tool execution.
- (decision) State Ownership: Stateless / File-System First. Binds: Project context is queried on the fly from disk or LSP. Prevents: Global in-memory state caches and flaky file-watchers.

- (event) Resumed session to update architecture based on UX and Feature Specs.
- (decision) File Explorer: Adopt oil.nvim exclusively instead of neo-tree. Binds: File management workflows. Prevents: Traditional sidebar abstraction layers; enforces standard Neovim buffer interactions for filesystem mutations.
- (decision) UI Coupling: Direct coupling to Snacks and Telescope. Binds: Feature modules rendering UI. Prevents: Over-engineered facade/adapter layers for UI components.
- (decision) Intelligence Boundary: Strict Native Intelligence. Binds: All new feature logic, parsing, and project discovery. Rule: New logic must be implemented in pure Lua (leveraging Tree-sitter) or delegated to an LSP. Prevents: Adding new surface area to the legacy Scala tetravim-engine or introducing external bash/python scripts for parsing.
