topic: Cumulus IDE Lua Migration
updated: 2026-08-25T04:21
---

- (decision) Why: Migrate away from custom Scala backend to pure Lua and LSPs to align with Neovim standards and eliminate blocking.
- (capability) CAP-1: Cloud Theme System - Dynamically switch UI accents based on AWS, Azure, GCP, OCI using native highlight overrides.
- (capability) CAP-2: Spring Ecosystem Integration - Pick and navigate to Spring Beans and REST endpoints via Tree-sitter AST parsing.
- (capability) CAP-3: Build System Mastery - Execute Maven/Gradle builds headlessly (vim.system) and populate inline error diagnostics.
- (capability) CAP-4: Buffer-based File Explorer - Navigate and mutate the file system strictly via oil.nvim buffers.
- (constraint) Must not add any new Scala/SBT code. The legacy cumulus-engine must not gain new surface area.
- (constraint) Core logic must remain UI-agnostic by emitting autocommands rather than calling render functions directly.
- (constraint) No global project state caches; context must be fetched on-the-fly from disk or LSP.
- (decision) Non-goal: Creating adapter facades for UI plugins. Direct coupling to snacks.nvim and Telescope is mandated.
- (decision) Non-goal: Retaining traditional sidebars for file navigation (neo-tree).
- (decision) Success Signal: A developer can debug a JVM app and discover Spring endpoints without the legacy scala engine binary running, and without editor UI freezes during background tasks.
- (event) Self-Validate Pass 1 & 2 completed: Coherence and Preservation verified.
- (event) spec finalized
- (decision) User approved proceeding with stories for Epic 1. Default checkpoints and dispatch notes proposed.
